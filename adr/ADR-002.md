# ADR-002: Containerize the server and validate locally

Spec: [`specs/SPEC-002.md`](../specs/SPEC-002.md)

The point of this slice is to move from "ASP.NET Core app I run with `dotnet run`" to "OCI image I can ship to ACR." Nothing about MCP, tools, or auth changes — only packaging and process lifecycle. Decisions:

- **Multi-stage Dockerfile.** Build stage uses the SDK image; runtime stage uses the much smaller ASP.NET runtime image. Standard pattern; produces a slimmer final image and keeps build tooling out of the deployed surface.
- **Base images:**
  - Build: `mcr.microsoft.com/dotnet/sdk:10.0`
  - Runtime: `mcr.microsoft.com/dotnet/aspnet:10.0`
  - Sticking with the standard Debian-based images, not the chiseled or Alpine variants. Chiseled images (`-noble-chiseled`) are smaller and lock down the attack surface, but they're a separate axis worth its own slice if/when we care. Default first, optimize later.
- **Local container runtime: podman.** Dockerfile content is unchanged — podman reads Dockerfiles natively and the build/run CLI is intentionally docker-compatible. The build artifact (an OCI image) is identical to what docker would produce, so it pushes to ACR and runs in Container Apps without translation.
- **Non-root user.** .NET 8+ ASP.NET runtime images run as the `$APP_UID` user by default. We inherit this for free — no explicit `USER` directive needed. Worth knowing it's there, and pairs naturally with podman's rootless default.
- **Port story.** Container listens on **8080** inside (standard for modern aspnet images; non-root can't bind <1024 anyway). Local dev outside the container keeps **3001** from SPEC-001. We map `-p 3001:8080` so the Inspector workflow from SPEC-001 doesn't change.
- **Program.cs binding change.** SPEC-001 hardcoded `app.Run("http://localhost:3001")`. That doesn't work in a container (binds to loopback, container traffic comes from outside). Change to bare `app.Run()` and let ASP.NET Core read the bind URL from `ASPNETCORE_URLS`. Local dev gets 3001 from `launchSettings.json` (which `dotnet new web` already wrote). Container gets `http://+:8080` from the base image's default `ASPNETCORE_URLS` env var. Same code, two environments, no `#if DEBUG` shenanigans. This is the shape every later deployment target wants too.
- **`.dockerignore` is non-optional.** Without it, the image build ships `bin/`, `obj/`, `.git/`, and possibly secrets into the build context. Smaller context = faster builds; clean context = no leaks. (podman honors `.dockerignore` identically; also accepts `.containerignore` if you prefer.)
- **No HEALTHCHECK directive, no entrypoint script.** Container Apps will provide its own health probes in SPEC-003; defer.
- **No image push yet.** This slice ends at `podman run` locally. ACR + Container Apps lives in SPEC-003.

Out of scope: image size optimization, layer caching micro-tuning, BuildKit secrets, multi-arch builds. All worth doing eventually; none worth doing now.
