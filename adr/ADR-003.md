# ADR-003: Push to ACR, deploy to Container Apps

Spec: [`specs/SPEC-003.md`](../specs/SPEC-003.md)

This slice takes the local image from SPEC-002 and stands up the real Azure surface: a registry, a Container Apps environment, and a Container App pulling from that registry over RBAC. Decisions:

- **Tooling: explicit `az` CLI commands.** Not `azd up`, not `az containerapp up`, not Bicep, not Terraform. Reason: pedagogy. Each Azure resource gets its own command, with its own arguments visible. Codifying into Bicep is a worthwhile future slice once we understand what's actually being created. `az containerapp up` is the magic-button alternative — fine, but hides exactly the things we want to learn.
- **Image build: `az acr build`.** Source goes to ACR, ACR builds and stores. Sidesteps the `docker login` against the registry dance and works even if local Docker is grumpy. We've already validated local `docker build` in SPEC-002; reusing that path (`docker push` to ACR) is the alternative and is noted below.
- **Auth between Container App and ACR: user-assigned managed identity (UAMI) with `AcrPull`.** Admin user on ACR stays **disabled**. UAMI chosen over system-assigned because (a) it survives Container App recreation, (b) it can be granted Key Vault permissions in SPEC-010 without duplicating identities, (c) it makes the role-assignment-before-resource sequencing trivial (no chicken-and-egg). One identity, many resources — clean.
- **Ingress: external, HTTPS only, target port 8080.** Azure terminates TLS at the ingress with its wildcard cert. Public FQDN format: `<app-name>.<random>.<region>.azurecontainerapps.io`. No custom domain this slice.
- **Scale: `min-replicas 0`, `max-replicas 1`.** Single-user tool, scale-to-zero when idle = free or near-free within the Container Apps monthly grant (180k vCPU-seconds, 360k GiB-seconds). One replica is plenty; we'll never benefit from more.
- **Resource sizing: 0.25 vCPU / 0.5 GiB.** Smallest Container Apps profile. A Hello-world MCP server doesn't need more.
- **SKUs:** ACR **Basic** (cheapest, ~$5/mo flat). Container Apps Consumption profile (pay-per-use, scales to zero).
- **Region: East US 2** by default (matches the existing `tidal-sonics-ca-poc` URL you already had; pick another if you'd rather).
- **Image tag: `v1`.** Avoiding `:latest` from the start — immutable tags make "which image is actually running" answerable, which matters once we have more than one version. Tag bumps are manual for now; CI/CD is a later concern.
- **No auth on the MCP server itself.** The Hello tool is harmless and the URL is unguessable, but this is not real security — it's a temporary state that exists for ~1 slice. **Don't share the URL.** SPEC-006 puts Google OAuth in front of it before any TIDAL access goes in.

Out of scope: Bicep / IaC, custom domain, CI/CD pipeline, log analytics workspace beyond the default one Container Apps creates, monitoring beyond `az containerapp logs show`.
