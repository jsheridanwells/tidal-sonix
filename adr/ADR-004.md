# ADR-004: Register the MCP server as a claude.ai custom connector

Spec: [`specs/SPEC-004.md`](../specs/SPEC-004.md)

The server is live and Inspector can drive it (SPEC-003). This slice closes the loop end-to-end: claude.ai sees the tool and can call it from inside a real conversation. The work is mostly procedural; the value is in proving the connector handshake and capturing where things break if they break. Decisions:

- **No OAuth on the MCP server this slice.** The "OAuth Client ID / Client Secret" fields under Advanced settings in the claude.ai connector flow are left blank. Anthropic's docs explicitly mark those as optional. SPEC-006 puts Google OAuth federation in front of the server before any TIDAL access work begins; until then the URL is the only thing between the internet and a Hello tool.
- **URL treated as a secret.** Not real security, but the only access control we have right now. Don't paste it into shared docs, slack threads, public commits, screenshots, or chat logs. Removed from the repo if it ever appeared there.
- **No IP allowlisting yet.** Container Apps can be fronted with IP restrictions limited to Anthropic's published IP ranges, which would tighten this slice's exposure considerably. Deferring: it's a defense-in-depth axis that gets cheaper to implement after SPEC-006 establishes the OAuth posture, and the Hello tool is genuinely harmless. Flagged in Notes as the next hardening step if you want to do it before SPEC-006.
- **MCP endpoint path = `/mcp`.** Pinned via `app.MapMcp("/mcp")` if you left it at the default in SPEC-001. The remote-MCP convention (and the path most existing Container-Apps-hosted MCP servers use) is `/mcp`; aligning now means the registered URL matches what every other tutorial and tool expects, and we don't have to revisit this when Inspector / claude.ai / desktop clients differ on default-path behavior.
- **Validate via real conversation, not just connector status.** A "Connected" badge means the protocol handshake succeeded, not that tool invocation works end-to-end. The success criterion is a Claude turn that calls `Hello` and returns the greeting.
- **Tail logs during first connect.** Container Apps logs are the diagnostic surface if anything fails. Have `az containerapp logs show --follow` running in a terminal *before* clicking Add, so any handshake errors are visible in real time.

Out of scope: OAuth (SPEC-006), IP allowlisting, custom domain, log analytics queries beyond live tailing, prompts and resources (we only have a tool), Claude Desktop / Cowork / mobile (same connector mechanism, but no need to re-validate three times).
